# OLIMP — система обліку спортивного клубу

Вебзастосунок для управління спортивним клубом: розклад тренувань,
онлайн-запис, абонементи, оплати, відвідування, сповіщення, живий чат
з адміністратором та АІ-асистент із фітнесу на локальній LLM.

## Можливості

- **Клієнт** — особистий кабінет, запис на тренування, перегляд розкладу,
  абонемент, історія активності, антропометрія, АІ-асистент з тренувань.
- **Тренер** — власний розклад, нотатки по клієнтах, спеціалізація.
- **Адміністратор** — клієнти, тренери, розклад, послуги, тарифи,
  розсилки (усім / групі / вибраним особам), живий чат із відвідувачами.
- **Керівник** — користувачі та ролі, фінансова аналітика, звіти.
- **Системні сповіщення** (дзвіночок зі звуком): наданий абонемент,
  перенесення/скасування заняття, новий запис на тренування.
- **PWA** — сайт можна встановити на телефон; адаптивна верстка під смартфон.
- **2FA** — вхід із підтвердженням кодом на email (опційно).

## Стек

| Шар | Технології |
|---|---|
| Бекенд | Node.js, Express (REST), JWT-автентифікація |
| БД | PostgreSQL, автоматичні SQL-міграції при старті |
| Фронтенд | Ванільні HTML/CSS/JS (ES-модулі), без збірки |
| АІ-асистент | Ollama + qwen3:8b (локальна LLM, працює офлайн) |
| Інфраструктура | Docker Compose (БД, застосунок, опційно Ollama) |

## Швидкий старт

```bash
# 1. Залежності
npm install

# 2. Конфігурація
cp .env.example .env        # заповніть PGPASSWORD і JWT_SECRET
                            # (JWT_SECRET: openssl rand -hex 32)

# 3. База даних у Docker (при першому старті схема створюється сама)
docker compose up -d db

# 4. Тестові дані (опційно)
npm run db:seed

# 5. Запуск (міграції застосуються автоматично)
npm run dev
```

Застосунок буде на <http://localhost:3000>.

## Тестові акаунти

Створюються командою `npm run db:seed`. Пароль у всіх однаковий: **`admin123`**.

| Роль | Email | Примітка |
|---|---|---|
| Адміністратор | `admin` | 2FA обов'язкова |
| Керівник (manager) | `manager@olimp.ua` | 2FA обов'язкова |
| Тренер | `anna@olimp.ua` (також `ihor@`, `maksym@olimp.ua`) | вхід одразу |
| Клієнт | `olena@mail.com` (також `daryna@`, `serhii@`, … `@mail.com`) | вхід одразу |

Для admin/manager другий крок входу — код 2FA. Без налаштованого SMTP (dev-режим)
код повертається у відповіді логіну як `devCode` і друкується в консоль сервера
(`[2FA] (DEV) код для …`); з SMTP — надсилається на email. Для діагностики з
увімкненим SMTP можна задати `DEBUG_OTP=1`, щоб код дублювався в консоль.

Сід ідемпотентний — повторний запуск не створює дублікатів користувачів
(лише додає нові платежі/відвідування до статистики).

## АІ-асистент

Асистент відповідає клієнтам на питання про тренування у вкладці
«АІ-асистент» чат-віджета. Працює на локальній моделі — дані нікуди
не надсилаються. Без Ollama решта системи працює як звичайно,
асистент лише повідомить, що тимчасово недоступний.

```bash
brew install ollama
ollama pull qwen3:8b
```

Далі нічого робити не треба: `npm run dev` сам підніме Ollama у фоні
(хук `predev`). Адреса й модель налаштовуються у `.env`
(`OLLAMA_URL`, `OLLAMA_MODEL`).

## Запуск повністю в Docker

```bash
docker compose up -d                     # БД + застосунок, Ollama на хості
docker compose --profile ollama up -d    # + Ollama в контейнері
```

Для контейнерної Ollama розкоментуйте в `.env`
`OLLAMA_DOCKER_URL=http://ollama:11434` — модель завантажиться
автоматично при першому старті (на macOS контейнер працює без GPU,
тому для розробки швидша нативна Ollama).

## Скрипти

| Команда | Дія |
|---|---|
| `npm run dev` | Dev-сервер із перезапуском (nodemon) + автозапуск Ollama |
| `npm start` | Продакшн-запуск |
| `npm run db:migrate` | Застосувати міграції вручну |
| `npm run db:seed` | Наповнити БД тестовими даними |
| `./scripts/db-backup.sh` | Резервна копія БД у `backups/` (gzip, ротація 30 днів) |

## Резервне копіювання БД

Основний (кросплатформенний) механізм — сервіс `db-backup` у `docker-compose.yml`:
окремий контейнер з cron, який щодня о 10:00 (Київ) робить `pg_dump`, стискає у
`backups/sports_club_db_<дата>.sql.gz`, перевіряє повноту дампа і видаляє копії,
старші за 30 днів. Якщо о 10:00 стек не працював — пропущений бекап виконується
одразу при наступному старті. Працює однаково на macOS, Windows і Linux; нічого
налаштовувати не треба — сервіс піднімається разом зі стеком:

```bash
docker compose up -d          # db + app + db-backup
# лог:            docker compose logs db-backup   (або backups/db-backup.log)
# бекап вручну:   docker compose exec db-backup sh /usr/local/bin/db-backup-cron.sh
```

Запасний варіант без compose-стека — локальний скрипт `scripts/db-backup.sh`
(macOS/Linux): запускається вручну або через launchd
(`scripts/com.olimp.db-backup.plist`, інструкція в коментарі файлу) чи cron.

Відновлення з копії (дампи створюються з `--clean --if-exists`, тому команда
працює і в непорожню базу — старі об'єкти видаляються й створюються заново):

```bash
gunzip -c backups/sports_club_db_<дата>.sql.gz \
  | docker exec -i 67-db-1 psql -q -U postgres sports_club_db
```

Примітка: копії, створені до 2026-07-18, зроблені без `--clean` — їх можна
відновити лише в порожню базу (або спершу видалити схему вручну).

## Структура проєкту

```
server/          Express-бекенд
  routes/        REST-маршрути (по модулю на сутність)
  middleware/    JWT-автентифікація та ролі
  utils/         константи, пошта, OTP, сповіщення
  migrate.js     автозастосування міграцій при старті
public/          фронтенд (роздається як статика)
  pages/         сторінки за ролями (client / trainer / admin / manager)
  js/            логіка сторінок, чат-віджет, сповіщення
  styles/        стилі (client.css — базовий, решта — поверх нього)
db/
  schema.sql     базова схема БД
  migrations/    інкрементальні зміни схеми
scripts/         службові скрипти (міграції, сіди, автозапуск Ollama)
```

## Розробка

- Код пишеться за «Корпоративним стандартом кодування» (див. `CLAUDE.md`):
  2 пробіли, рядок ≤100 символів, JSDoc, коментарі українською.
- Після зміни CSS/JS перед пушем підніміть версію кешу в `public/sw.js`
  (`CACHE_NAME`), інакше PWA-користувачі побачать старі файли.
- Робочі гілки зливаються у `beta`; `main` — стабільна.
